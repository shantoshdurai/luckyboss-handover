# LUCKY BOSS PORTAL

## AI-Powered Recruitment Platform – Detailed Website, Mobile App, Admin Control & Workflow Specification

### Proposed Technology

* Backend / Admin Portal: Laravel
* Public Website: Laravel / responsive web frontend
* Mobile Application: Flutter for Android & iOS
* Database: MySQL
* AI Layer: OpenAI APIs + Resume Parser + Embeddings + Vector Search
* Cloud: AWS / Google Cloud
* Notifications: Firebase
* Email: SendGrid / Mailgun
* WhatsApp: WhatsApp Cloud API
* Voice: Twilio Voice API
* Payments: Razorpay / Stripe / supported regional gateways
* Calendar: Google Calendar API
* Multi-Currency: SGD, INR, MYR/Ringgit and additional currencies configurable by Admin

---

# 1. PROJECT VISION

Lucky Boss Portal will be a complete AI-enabled recruitment ecosystem connecting:

1. Job Seekers
2. Employers / Companies
3. Recruitment Administrators
4. Internal Recruitment Team
5. External Job Data Sources
6. AI Matching & Automation Services

The platform will be developed so that AI and paid third-party APIs are not permanently hard-coded into the business process.

Every major paid tool or AI feature will have an Admin ON/OFF control.

Example:

OpenAI Resume AI: ON
→ AI Resume Builder and AI Resume Analysis are shown.

OpenAI Resume AI: OFF
→ Those AI features disappear from Website/App and users continue with manual resume functionality.

This approach protects the platform from depending entirely on third-party providers and allows the company to control operational costs.

# 32. TABLE 1 – ORGANIC APPLICANTS

These are candidates who directly applied for the employer's job.

Example:

| Candidate   | Match | Experience | Skills | Location  | Status  |
| ----------- | ----: | ---------- | ------ | --------- | ------- |
| Candidate A |   92% | 5 Years    | 8/10   | Singapore | Applied |
| Candidate B |   86% | 4 Years    | 7/10   | Malaysia  | Applied |

Organic means:

Candidate saw job
→ Candidate clicked Apply
→ Application was submitted.

---

# 33. TABLE 2 – SYSTEM RECOMMENDED CANDIDATES

Lucky Boss Portal automatically searches its internal candidate database.

The system compares:

Job Description

* Skills
* Experience
* Education
* Location
* Salary
* Candidate Preferences

Then recommends suitable candidates even if they have not applied.

Example:

| Candidate   | AI Match | Experience | Skill Match | Availability |
| ----------- | -------: | ---------: | ----------: | ------------ |
| Candidate C |      95% |    6 Years |         96% | Immediate    |
| Candidate D |      88% |    5 Years |         90% | 30 Days      |

Employer can invite these candidates to apply.

---

# 34. TABLE 3 – THIRD-PARTY / EXTERNAL JOB MARKET DATA

Optional module controlled completely by Admin.

Possible sources may include licensed feeds, official APIs, recruitment partners or legally/permissibly available public recruitment information.

The platform should not depend on unauthorized scraping or bypassing protections of sites such as LinkedIn or Naukri.

Where an external source permits integration, the record can show:

| Candidate/Lead | Source              | Role       | Match | Available Contact |
| -------------- | ------------------- | ---------- | ----: | ----------------- |
| External Lead  | Partner Feed        | Engineer   |   89% | Available         |
| External Lead  | Approved Job Source | Supervisor |   81% | Available         |

The source should always be displayed clearly.

Admin:

Third-Party Candidate Data
ON/OFF

If OFF, the entire third table disappears from Employer Portal.

# 99. RECOMMENDED DEVELOPMENT PRINCIPLE

All business controls should be data-driven.

Avoid coding statements such as:

"Candidate payment is always free."

Instead:

```text
candidate_payment_enabled = false
```

Admin changes it later to:

```text
candidate_payment_enabled = true
```

Similarly:

```text
ai_resume_enabled
ai_chat_enabled
third_party_jobs_enabled
voice_interview_enabled
whatsapp_enabled
candidate_paid_jobs_enabled
```

This makes Lucky Boss Portal highly configurable.
